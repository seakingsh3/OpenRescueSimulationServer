🧭 Überblick & Bedienung

OpenRescueSim zeichnet Übungen mit mehreren Kameras auf, überträgt sie live an Zuschauer-Viewer und lässt Ausbilder während der Übung Marker setzen, die im Debriefing angesprungen werden können.

Aufbau der Oberfläche

  • Seitenmenü links: Dashboard, Simulieren, Debriefen, Zuschauen, Teilnehmer, Optionen (Systemstatus, Einstellungen, User-Stats, Achievements) und Hilfe. Auf kleinen Bildschirmen öffnet es sich über das Menü-Symbol oben links.
  • Kopfleiste: Login-Knopf (Schloss) bzw. Logout, dazu die Session-Statusleiste. Sie zeigt, ob eine Session läuft, und blinkt rot mit Einloggen, wenn du für die aktuelle Seite angemeldet sein musst.
  • Schwebende Aktionsknöpfe (FAB) am rechten Rand: Start, Stop, Viewer, PTT und Sessions löschen. Sie sind auf jeder Seite erreichbar.
  • Toasts: Kurze Meldungen unten bzw. oben rechts bestätigen Aktionen oder zeigen Fehler. Achievements erscheinen als eigene Toasts.
  • Thema: Unten im Seitenmenü zwischen Hell und Dunkel umschalten. Die Wahl wird im Browser gespeichert.

Rollen

  • Nicht eingeloggt: Nur öffentliche Inhalte, also Zuschauer-Viewer, QR-Generator, Teilnehmer-Notizblätter, Ticker und Trivia.
  • Nutzer: Simulation starten und stoppen, Marker setzen, Debriefing, Sessions der letzten 24 Stunden, Kameras und Räume ansehen, Statistiken.
  • Admin: Zusätzlich alle Sessions, Benutzerverwaltung, Aufnahme- und Ausgabe-Einstellungen, Systemaktionen, Updates, Logdateien.
Diese Hilfe ist genauso aufgeteilt: Was nur Admins betrifft, ist mit Admin markiert und über den Expertenmodus oben einblendbar.

🔒 Anmeldung & Konten

Einloggen

  1. Oben rechts auf das Schloss-Symbol klicken oder in der roten Statusleiste auf Einloggen.
  2. Benutzername und Passwort eingeben. Enter löst den Login aus.
  3. Nach erfolgreichem Login lädt die Seite neu. Oben erscheint Logout.
Ein 401-Hinweis oder eine rote Statusleiste bedeutet immer: Anmeldung erforderlich oder abgelaufen. Einmal neu einloggen genügt.

Konto mit Einladungs-Token anlegen (Selbstregistrierung)

  1. Vom Admin einen Einladungs-Token erhalten (fünfstelliger Code).
  2. Optionen → Einstellungen → Reiter Benutzer & Zugang öffnen.
  3. Im Kasten Anmeldung per Token Token, gewünschten Benutzernamen und Passwort eintragen.
  4. Registrieren klicken, danach normal einloggen.

Einladungs-Token erzeugen Admin

  1. Als Admin einloggen, Einstellungen → Reiter Benutzer & Zugang.
  2. Im Bereich Benutzerverwaltung unten auf 🔑 Token erzeugen klicken.
  3. Der Token erscheint im Feld daneben, mit Kopieren in die Zwischenablage. Jeder Token ist einmal verwendbar.

Benutzer direkt anlegen oder löschen Admin

  1. Im Bereich Benutzerverwaltung Benutzername, Passwort und Rolle (user oder admin) eintragen.
  2. ＋ Benutzer anlegen klicken. Die Tabelle aktualisiert sich, ↻ Aktualisieren lädt sie neu.
  3. Zum Entfernen in der Tabellenzeile auf die Aktion Löschen klicken. Der eigene Admin-Account lässt sich nicht selbst entfernen.
Der Pseudo-Nutzer Teilnehmer gehört zu den Notizblättern und ist in der Liste ausgeblendet. Bitte nicht manuell anlegen oder umbenennen.

Ausloggen

Oben rechts Logout klicken. Token und Benutzername werden im Browser gelöscht, die Seite lädt neu.

🧱 Server installieren (Root-Ebene) Admin

Reproduzierbare Installation auf Debian 13 (Trixie) oder Debian 12 mit Backports-Kernel. Der Dienst läuft als eigener Benutzer openresquesim (Gruppen audio und video für Audio-Interfaces und Kameras), nicht als root. Was root braucht – HTTPS einrichten, Update installieren, Rechner neu starten oder herunterfahren –, ist einzeln in /etc/sudoers.d/openresquesim freigegeben. Alle Daten liegen unter /var/lib/openresquesim.

Schnellweg: geführte Installation mit dem Paket

sudo apt install ./openresquesim-server_*.deb

Mit apt (nicht dpkg -i) werden alle benötigten Fremdpakete mitinstalliert: GStreamer mit Plugins, FFmpeg, mkcert, NSS-Tools, empfohlen auch Avahi und ALSA-Werkzeuge. Die Installation fragt dann:

  1. Port der Weboberfläche (Standard 8393).
  2. HTTPS jetzt einrichten? Mit Namen/IPs fürs Zertifikat (leer = automatisch) und HTTPS-Port (Standard 8443).
  3. Firewall öffnen? Nur wenn ufw aktiv ist: Weboberfläche, HTTPS und UDP für WebRTC.

Danach läuft der Dienst openresquesim (startet auch nach einem Neustart), und die Installation zeigt die Adresse. Im Browser legt der Einrichtungsassistent das Admin-Konto an. Die Schritte 1–5 und 9 unten sind damit erledigt.

  • Antworten ändern: sudo dpkg-reconfigure openresquesim-server
  • Ohne Fragen (Standardwerte): sudo DEBIAN_FRONTEND=noninteractive apt install ./openresquesim-server_*.deb
  • Ohne Internet: Die Fremdpakete müssen aus einer lokalen Paketquelle kommen oder schon installiert sein.
  • Entfernen: sudo apt purge openresquesim-server löscht Dienst, Einstellungen und Zertifikate; Datenbank und Aufnahmen bleiben.
Eine früher von Hand angelegte /etc/systemd/system/openresquesim.service hat Vorrang vor der Unit aus dem Paket. Zum Umstieg löschen und sudo systemctl daemon-reload ausführen.

Von Hand (ohne Paket oder zum Nachvollziehen)

1 · Voraussetzungen

  • Rechner mit Debian, Netzwerk per Kabel, Zugriff als root oder mit sudo.
  • Für Übungsräume mit vielen Kameras mindestens vier CPU-Kerne; die Kameras liefern H.264 per RTSP.
  • Optional ein USB-Audio-Interface für den Raumton. Für die Routing-Matrix einer Scarlett Gen 4 wird Kernel 6.8 oder neuer gebraucht.

2 · Laufzeitpakete

Aus dem Projektordner, oder mit dem Skript, das dem fertigen Paket beiliegt:

sudo ./scripts/install_runtime_deps.sh

Das installiert GStreamer mit den Plugin-Sätzen base, good, bad, ugly, libav, alsa und nice sowie OpenSSL und SQLite. Zusätzlich für die VOD-Aufbereitung:

sudo apt install -y ffmpeg alsa-utils
Ohne gstreamer1.0-nice gibt es kein WebRTC („libnice elements are not available“), ohne ffmpeg keine Aufzeichnung als VOD.

3 · Programm installieren

Entweder als Debian-Paket oder als Binary aus dem Quellbaum.

  1. Paket bauen (auf einem Rechner mit Rust-Toolchain): cargo install cargo-deb, dann im Projekt cargo deb. Das Paket liegt danach unter target/debian/openresquesim-server_*.deb und enthält Binary, Web-Oberfläche, Hilfe, Desktop-Eintrag und Icon.
  2. Paket installieren: sudo apt install ./openresquesim-server_*.deb (geführt, siehe oben). Das Binary landet als /usr/bin/openresquesim-server, die Web-Dateien unter /usr/share/openresquesim/web.
  3. Alternative ohne Paket: cargo build --release und target/release/openresquesim_server nach /usr/bin/openresquesim-server kopieren; den Ordner src/web nach /usr/share/openresquesim/web.

6 · Erststart

  1. Admin-Konto und Grunddaten per Skript anlegen: sudo ./scripts/first_start.sh -p 'SicheresPasswort'. Optional Marker-Typen mit --marker-type "Alarm" "#ff0000".
  2. Alternativ im Browser http://<server>:8393/setup öffnen und den Assistenten ausfüllen, siehe Erstinstallation.
  3. Danach http://<server>:8393/ui aufrufen und als Admin einloggen.

Die Kartennummer aus arecord -l einsetzen. Mehrkanal-Interfaces erkennt der Server automatisch, die Kanalwahl steht in den Räumen, siehe Kameras & Räume.

8 · Netzwerk und Firewall

  • TCP 8393 (HTTP) und optional TCP 8443 (HTTPS) eingehend erlauben.
  • WebRTC und Durchsagen nutzen UDP. Im Übungsnetz UDP eingehend komplett erlauben, etwa mit nftables udp accept oder ufw allow 1024:65535/udp.
  • Für die Raumlautsprecher UDP 5004 eingehend auf den Pi-Geräten offen halten.
  • Feste IP oder DHCP-Reservierung für den Server, damit Viewer-Links und QR-Codes gültig bleiben.

9 · HTTPS und Lautsprecher

HTTPS für die Durchsage-Geräte: sudo ./scripts/setup_https.sh, Details unter HTTPS einrichten. Raumlautsprecher auf dem Raspberry Pi (aus dem Geräte-Repository OpenRescueSim-Devices, Ordner speaker_pi/): sudo ./install_speaker.sh <server>:8393 "Simraum 1" simraum, Details unter Audio & Durchsagen.

10 · Updates

  • Über die Oberfläche: Einstellungen → Aufnahme & Ausgabe → Update: signiertes Paket hochladen und installieren (Schlüssel einrichten: siehe dort). Das Log läuft live mit, der Dienst startet am Ende neu.
  • Auf der Konsole: sudo apt install ./openresquesim-server_*.deb. Der Dienst startet von selbst neu; Einstellungen und Zertifikat bleiben.
  • Neue Abhängigkeiten eines Updates holt apt mit. Ohne Internet und ohne lokale Paketquelle bricht das Update dann mit einer Meldung ab, die alte Version läuft weiter.
  • Die Datenbank wird beim Start automatisch migriert. Vor Updates /var/lib/openresquesim sichern.

11 · Backup und Diagnose

  • Backup: /var/lib/openresquesim (Datenbank und Aufnahmen) und /etc/openresquesim (Zertifikate) sichern. Aufnahmen können groß werden, alte Sessions in der App löschen.
  • Logs live: journalctl -u openresquesim -f -o cat. Tägliche Dateien in der Systemseite unter „Dateien“.
  • Tiefe GStreamer-Diagnose zeitweise in der Unit: Environment=GST_DEBUG=webrtc*:6,nice*:6,alsa*:6,*:3, danach daemon-reload und Neustart.
  • Startet der Dienst nicht: gst-inspect-1.0 --version und die Paketliste aus Schritt 2 prüfen.

🛠 Erstinstallation Admin

Beim ersten Start ohne abgeschlossenes Setup öffnet sich der Assistent unter /setup. Er kann jederzeit dort erneut aufgerufen werden, solange das Setup nicht abgeschlossen ist.

  1. Admin & Sicherheit: Admin-Benutzername (Standard admin), Passwort und den Auth-Schlüssel eingeben. Generieren erzeugt einen zufälligen Schlüssel.
  2. Aufnahme & Ausgabe: Recording aktiv, Container (mkv/mp4/mov), Segmentlänge in Sekunden, maximale Dateien (0 = unbegrenzt), Dateiprefix, Aufnahmeverzeichnis und Audio-Device festlegen.
  3. Marker-Typen: Standard-Typen mit Name und Farbe anlegen oder über + Hinzufügen ergänzen.
  4. Textbausteine: Vorschläge für Marker-Notizen anlegen.
  5. Kameras: Erste Kameras mit Name und Stream-URL eintragen.
  6. Setup abschließen klicken. Danach ist die App unter /ui nutzbar.
Das Setup ist auch per Kommandozeile möglich, etwa openresquesim_server setup --admin-password …. Die Datenbank liegt standardmäßig unter ~/.local/share/openresquesim/app.db, änderbar per ORS_DB_PATH.

🎬 Simulation starten & stoppen

Seite Simulieren. Eine laufende Simulation heißt Session. Es kann immer nur eine Session aktiv sein.

Session starten

  1. Auf den grünen Start-Knopf (FAB rechts) klicken oder Strg+S drücken.
  2. Im Dialog einen Session-Namen eingeben. Ohne Eingabe wird ein Name mit Zeitstempel vorgeschlagen.
  3. Optional Viewer auswählen, die den Livestream erhalten sollen (siehe Viewer). Ohne Auswahl bekommen alle verbundenen Viewer das Bild.
  4. Optional einen Raum wählen. Der Raum legt Layout, Kameras, Audio-Gerät, Lautsprecher und Standard-Viewer fest (siehe Kameras & Räume).
  5. Optional Vor-Start (Ausbilder benachrichtigen) auslösen anhaken, siehe unten.
  6. OK klicken. Während die Pipeline aufgebaut wird, erscheint „Pipeline wird vorbereitet…“, danach „Session gestartet“.
Ist der Session-Name bereits vergeben, wird automatisch ein Zusatz angehängt und die Session trotzdem gestartet.

Vor-Start mit Freigabe

Mit angehaktem Vor-Start wird die Pipeline bereits aufgebaut, aber ohne Aufnahme und ohne Übertragung an Zuschauer: Ausbilder-Viewer (Rolle „Ausbilder“) sehen den Livestream sofort zur Kontrolle, alle UIs sehen einen Toast „Vor-Start“. Alle anderen Viewer (Zuschauer/Teilnehmer) sehen währenddessen kein Bild, sondern nur ein Hinweis-Banner „Start steht bevor – bitte bereit machen!“ auf ihrem Ruhebildschirm. Erst der schwebende Freigeben-Knopf am rechten Rand startet Aufnahme und Stream für alle Viewer wirklich und blendet das Banner aus. So lässt sich der Beginn exakt timen, ohne dass Zuschauer vorzeitig etwas sehen.

Vor-Start abbrechen: Stop beendet einen Vor-Start ohne Freigabe. Die vorbereitete Session wird dann verworfen (sie taucht nicht in der Session-Liste auf, ein Debriefing gibt es nicht), Zuschauer kehren auf den Ruhebildschirm zurück. Ein neuer Vor-Start oder ein direkter Start ersetzt einen noch offenen Vor-Start automatisch, ebenso räumt ein Serverneustart ihn ab. Lädt man die Simulate-Seite neu, während der Vor-Start läuft, erscheint der Freigeben-Knopf wieder.

Session stoppen

  1. Roten Stop-Knopf klicken oder Strg+H.
  2. Die Aufnahme wird abgeschlossen und als VOD aufbereitet. Viewer wechseln zurück in den Ruhezustand.
  3. Anschließend fragt das Fenster Zum Debriefing wechseln, ob du direkt ins Debriefing springen willst: Zum Debriefing oder Abbrechen.

Notfall-Neustart

Bei aktiver Session zeigt die Seite oben den gelben Knopf 🚨 Notfall-Neustart (gleiche Vorgaben). Er stoppt die Session und startet sofort eine neue mit demselben Namen, denselben Viewern und demselben Raum, ohne Rückfragen. Sinnvoll, wenn Bild oder Ton hängen.

Statusleiste lesen

Die Leiste oben zeigt Name und Laufzeit der aktiven Session. Mit ↻ lässt sich der Status manuell nachladen. Rot blinkend bedeutet: nicht eingeloggt.

🏠 Raum live wechseln

Während einer laufenden Session kann auf einen anderen Raum umgeschaltet werden, ohne Aufnahme oder Zuschauer-Stream zu unterbrechen.

  1. Auf Simulieren die Karte Raum wechseln (live) nutzen. Sie ist nur bei aktiver Session sichtbar und zeigt den aktuellen Raum als Badge.
  2. Im Auswahlfeld den Zielraum wählen.
  3. Wechseln klicken. Nur Kameras, die sich ändern, werden getauscht. Diese Slots zeigen ein bis drei Sekunden ein Schwarzbild, bis die neue Kamera liefert.
  4. Das Layout wird sofort umgestellt, ein Marker „Raumwechsel → Raumname“ wird automatisch gesetzt, und der Standard-Viewer des Raums wird bei Bedarf angebunden.
Ein anderes Audiogerät im Zielraum kann kurz knacken. USB-Kameras müssen vom alten Slot freigegeben sein, bevor ein anderer Slot sie öffnen kann.

📺 Viewer & Zuschauer

Ein Viewer ist ein Anzeigegerät (Beamer, Monitor, Tablet), das die Seite /viewer/<ID> geöffnet hat. Viewer zeigen im Ruhezustand die Trivia-Slideshow mit Ticker, während der Session den Livestream und im Debriefing die Aufzeichnung.

Viewer anlegen und verwalten

  1. Gelben Viewer-Knopf (FAB) klicken. Das Fenster Viewer verwalten öffnet sich, die Zahl am Knopf zeigt die Online-Viewer.
  2. ＋ Neu legt einen Viewer an. Name (Alias) und Rolle festlegen: Ausbilder, Teilnehmer oder Sonstige. Die Rolle steuert, wer Vor-Start-Hinweise bekommt.
  3. Am Anzeigegerät die Adresse http://<Server-IP>:8393/viewer/<ID> öffnen. Ein neues Gerät zeigt zunächst „Bitte koppeln“ (siehe unten), danach meldet es sich als „online“.
  4. Für den Session-Start Viewer mit Häkchen auswählen, Alle auswählen oder Auswahl leeren nutzen. ↻ Aktualisieren lädt den Online-Status.

Bildschirme und Pager koppeln

Nur gekoppelte Geräte bekommen Bild und Durchsagen – wer nur die Adresse kennt, sieht nichts. Gekoppelt wird ein Gerät einmal, danach merkt es sich das im Browser.

  • Per QR-Code: Der QR-Code aus Zuschauer QR koppelt das Gerät beim Scannen gleich mit. Ebenso Öffnen und ＋ Neuen Viewer-Bildschirm öffnen in der Liveansicht.
  • Per PIN (z.B. PC am Beamer): Am Gerät erscheint „Bitte koppeln“ mit einem Zahlenfeld. In Einstellungen → Kameras & Räume → Aktive Viewer auf 📱 Gerät koppeln tippen und die angezeigte 6-stellige PIN am Gerät eingeben. Der Dialog meldet „✅ gekoppelt“.
  • QR-Code und PIN gelten 2 Minuten und nur für ein Gerät. Nach 10 falschen PINs werden offene PINs verworfen.
  • Die Liste Gekoppelte Geräte zeigt Nummer, Gerät und „zuletzt verbunden“. Entkoppeln nimmt einem Gerät sofort Bild und Ton; es fragt dann wieder nach der PIN.
  • Pager (/pager/<ID>) werden genauso gekoppelt. Viewer und Pager mit derselben Nummer teilen sich die Kopplung.
Nach dem Update auf diese Version müssen alle vorhandenen Bildschirme und Pager einmal gekoppelt werden, bis dahin zeigen sie „Bitte koppeln“.

Zuschauer per QR-Code einladen

  1. Dashboard-Karte Zuschauer QR öffnen (oder in der Liveansicht den Link unter „Viewer-Bildschirme“).
  2. Jetzt erstellen startet den Assistenten. Schritt 1: die Viewer-ID eintragen und mit OK bestätigen – jede ID ist ein eigener Viewer-Bildschirm.
  3. 🔗 Link generieren. Link (mit Server-IP und Port) und großer QR-Code erscheinen, Link kopieren kopiert die Adresse. Zurücksetzen beginnt von vorn.
  4. Zuschauer scannen den Code mit dem Handy und sehen den Stream im Browser. Der Server verwendet dafür automatisch seine Netzwerk-IP. Der Code koppelt das Gerät und gilt nur 2 Minuten und für ein Gerät – für jedes weitere Gerät den Link neu generieren.

Viewer-Fehlermeldungen

Meldet ein Viewer ein Problem (zum Beispiel keine Verbindung), erscheint in der Kopfleiste ein roter Hinweis. Details zeigt die Meldung, Bestätigen quittiert sie.

Liveansicht im Ausbilder-Browser

Die Seite Zuschauen (Liveansicht) zeigt das Bild der laufenden Übung direkt im Browser – ohne Einstellungen. Sie verbindet sich automatisch, sobald eine Session oder ein Vor-Start läuft, und zeigt sonst „Keine Session aktiv“. Der Ton ist zunächst aus (Browser-Vorgabe) und lässt sich mit 🔇 Ton aus einschalten; ⛶ Vollbild vergrößert das Bild.

Darunter listet Viewer-Bildschirme alle bekannten Anzeigen (/viewer/<ID>) mit Online-Status. Öffnen zeigt einen Bildschirm in einem neuen Tab, ＋ Neuen Viewer-Bildschirm öffnen nimmt die nächste freie ID. Jede offene Liveansicht und jeder Viewer kostet den Server etwa gleich viel Rechenleistung.

📍 Marker setzen

Marker sind Zeitmarken mit Typ, Farbe und optionalem Text. Sie werden nur bei laufender Session gesetzt und erscheinen im Debriefing auf der Zeitleiste. Ohne aktive Session weist ein Fenster darauf hin.

Marker mit Typ setzen

  1. Auf Simulieren im Bereich Marker den Eingabemodus Marker wählen (Schalter Marker/AMLS).
  2. Einen der farbigen Marker-Typ-Knöpfe antippen. Ein kleines Kbd-Zeichen am Knopf zeigt ein zugewiesenes Tastenkürzel.
  3. Im Fenster Marker-Notiz optional einen Text eintragen oder einen Textbaustein anklicken. Setzen speichert mit Text, Ohne Text ohne. Enter setzt ebenfalls.

Freitext-Marker

Text in Freitext für Marker eintragen und 📝 Freitext Marker setzen klicken. Der Marker bekommt den Typ „Freitext“, der bei Bedarf automatisch angelegt wird.

Papier-Marker

📝 Papier-Marker setzen setzt sofort einen Marker vom Typ „Papier“, etwa wenn Teilnehmer etwas auf Papier dokumentieren. Ein zugewiesenes Tastenkürzel wird am Knopf angezeigt.

Gesetzte Marker ansehen und löschen

  • Die Liste Gesetzte Marker zeigt eigene Marker und die anderer Nutzer, neueste zuerst. Jeder Eintrag zeigt ID, Typ, Zeit, Text und ein Vorschaubild.
  • ↻ lädt die Liste neu. Sie aktualisiert sich außerdem automatisch, wenn jemand Marker setzt.
  • Über die Löschen-Schaltfläche am Eintrag wird ein Marker entfernt.

Fokusmodus

Der Schalter Fokusmodus vergrößert die Marker-Knöpfe und blendet selten genutzte Aktionen aus, praktisch für Tablets während der Übung.

Marker an der Seite anheften

🩺 AMLS-Modus

Der AMLS-Modus bewertet die strukturierte Patientenversorgung. Er sieht aus wie das Einsatzformular und erzeugt Marker vom Typ „AMLS“.

  1. Im Marker-Bereich den Schalter auf AMLS stellen.
  2. Links unter Ersteinschätzung je Schritt Atemweg, Belüftung, Cirkulation, Defizite neurologisch, Entkleiden mit richtig oder falsch bewerten. Der Marker lautet dann etwa „ABCDE A: richtig“.
  3. Rechts SAMPLER (Symptome, Allergien, Medikamente, Patientenvorgeschichte, Letzte Mahlzeit, Ereignisse, Risikofaktoren) und OPQRST (Onset, Palliation, Qualität, Region, Schwere, Time) ebenso bewerten.
  4. Unter Entscheidung einen Diagnosehinweis in den Diagnosetrichter tippen und Setzen klicken. Marker: „Diagnosetrichter: …“.
  5. Unten die Priorisierung mit Kritisch oder Nicht kritisch setzen.
Innerhalb einer Zeile bleibt die letzte Wahl farbig markiert. Jeder Klick erzeugt einen neuen Marker, eine Korrektur ist also nachvollziehbar.

🎛 Marker-Tastenkürzel & Makro-Tastatur

Jedem Marker-Typ kann eine Taste zugewiesen werden. Ein Tastendruck setzt dann sofort einen Marker dieses Typs ohne Klick und ohne Notiz-Fenster.

Taste zuweisen

1–9 automatisch belegen verteilt die Ziffern der Reihe nach auf alle Typen ohne Taste.

Eigene Makro-Tastatur anschließen

🔌 Lautsprecher & On-Air-Lampe (ESP32)

Zwei kleine WLAN-Geräte ergänzen den Übungsbetrieb. Bedienen musst du sie kaum: Der Raumlautsprecher spielt Durchsagen aus dem Ausbilderraum im Simulationsraum ab, die On-Air-Lampe am Raumeingang leuchtet, solange eine Übung läuft.

Raumlautsprecher

Das Gerät ist per WLAN mit dem Server verbunden und gibt Durchsagen per Push-to-Talk (siehe Audio & Durchsagen) wieder. Der Ton geht über ein AUX-Kabel (3,5-mm-Klinke) an eine Aktiv- oder Bluetooth-Box, einen eigenen Lautsprecher hat das Gerät nicht.

  1. Box einschalten und auf AUX stellen (je nach Box per Taste oder automatisch, sobald das Kabel steckt).
  2. Gerät über USB-C mit Strom versorgen (USB-Netzteil oder PoE-Splitter).
  3. Ein kurzer Piepton aus der Box zeigt: Das Gerät ist gestartet.
  4. Nach wenigen Sekunden steht es unter Einstellungen → Kameras & Räume → Raumlautsprecher mit Status online.
  5. Steht dort nicht freigegeben (neue Firmware): einmal mit 📍 prüfen, welches Gerät piept, dann ✅ Freigeben. Das gilt dauerhaft, auch nach Neustarts.

On-Air-Lampe

Die Lampe am Raumeingang leuchtet automatisch, solange eine Übung läuft, und geht aus, wenn sie beendet wird. Bedienen musst du nichts.

  • Nach Start oder Ende einer Übung dauert es bis zu etwa 3 Sekunden, bis die Lampe umschaltet.
  • Während eines Vor-Starts bleibt sie aus. Sie geht erst mit Freigeben an, wenn Aufnahme und Stream wirklich laufen.
  • Ist der Server nicht erreichbar oder fällt das WLAN aus, geht die Lampe sicherheitshalber aus. Eine dunkle Lampe heißt also nicht in jedem Fall, dass keine Übung läuft.

Wenn die Lampe nicht reagiert:

  1. Hat die Lampe Strom?
  2. Läuft die Übung wirklich (gestartet bzw. freigegeben)?
  3. Gerät kurz vom Strom trennen und wieder anschließen, nur einmal (siehe Hinweis).
  4. Weiterhin Probleme: an die Administration wenden.
Achtung: Wird die Lampe innerhalb der ersten 5 Sekunden nach dem Einschalten erneut vom Strom getrennt, öffnet sie beim nächsten Einschalten ihren Einrichtungsmodus und ist bis zur Einrichtung außer Betrieb. Nach dem Wiedereinschalten also mindestens 5 Sekunden am Strom lassen.

Raumlautsprecher: Funktionsweise

  • Meldet sich per WebSocket unter ws://<server>:<port>/ws/voice/speaker an, gleiches Protokoll wie der Raspberry-Pi-Client speaker_pi/ors-speaker.py im Geräte-Repository.
  • Registriert sich mit codec: "l16". Der Server schickt solchen Geräten unkomprimiertes PCM (RTP/L16, 16 kHz, mono, Payload-Typ 97) statt Opus (eigener Zweig in src/voice.rs).
  • Audio kommt per UDP an Port 5006 am Gerät an und geht per I2S an DAC bzw. Verstärker.
  • Heartbeat alle 5 s (Lautstärke, Stumm, empfangene Pakete, Laufzeit).
  • Vom Server unterstützte Befehle: set_volume, mute, test_tone, identify, config (Name/Gruppe), reboot. reboot löst der Knopf ⟳ in der Lautsprecherliste aus.
  • Freigabe: Firmware mit Schlüssel-Unterstützung meldet key_support. Ohne gültigen Schlüssel erscheint das Gerät als „nicht freigegeben“ und bekommt keinen Ton; ✅ Freigeben schickt ihm einen Schlüssel (pair), den es dauerhaft speichert und bei jeder Anmeldung mitschickt. Einmal freigegebene Geräte müssen den Schlüssel immer zeigen; ein Gerät ohne Schlüssel kann ein freigegebenes mit derselben ID nicht verdrängen. Alte Firmware ohne Schlüssel und der Raspberry-Pi-Client laufen übergangsweise als „alt · ungesichert“ weiter. Protokoll: Handover_ESP32_Freigabe.md.
  • Geräte-ID: esp32- + MAC-Adresse ohne Doppelpunkte, z.B. esp32-28848568b644. Name, Gruppe und Lautstärke merkt sich der Server über diese ID.

Raumlautsprecher: WLAN und Server einrichten

Die WLAN-Zugangsdaten stehen nicht in der Firmware. Das Gerät speichert sie selbst (NVS), sie überstehen Neustarts und Firmware-Updates.

  1. Gerät ohne bekanntes WLAN starten. Es öffnet den Access Point ORS-Lautsprecher-XXXX (XXXX = letzte 4 Stellen der MAC), Passwort ors-setup. Zwei kurze Pieptöne zeigen den Einrichtungsmodus an.
  2. Mit dem Handy verbinden. Die Einrichtungsseite öffnet sich selbst, sonst http://192.168.4.1.
  3. Configure WiFi → WLAN wählen (nur 2,4 GHz), Passwort eingeben.
  4. Server-Adresse und Port prüfen (die eingebaute Vorgabe durch die Adresse des eigenen Servers ersetzen, Port 8393) → Save.
  • Das Portal schließt nach 3 Minuten ohne Eingabe. Das Gerät startet dann neu und versucht das gespeicherte WLAN.
  • Später ändern: BOOT-Taster am Board 3 Sekunden halten, dann öffnet sich das Portal. So auch nach einem Wechsel der Server-IP.
  • Ist das WLAN im Betrieb länger als 60 s weg, startet das Gerät neu.
  • Nach der Anmeldung erscheint das Gerät in der Lautsprecherliste als „Simraum ESP32“ in Gruppe default. Dort umbenennen und einer Gruppe zuordnen.

On-Air-Lampe: Funktionsweise

  • Fragt alle 3 s GET http://<server>:<port>/api/sim/status ab. Der Endpunkt braucht keinen Login, er steht serverseitig in is_public_api_path() in src/main.rs.
  • "active":true → Relais an, "active":false → Relais aus. Ein Vor-Start meldet "active":false (die Session ist noch nicht freigegeben), die Lampe bleibt dann aus.
  • Nach 3 fehlgeschlagenen Abfragen in Folge und bei WLAN-Verlust: Relais aus.
  • Ist das WLAN länger als 60 s weg, startet das Gerät neu.

On-Air-Lampe: Hardware

  • ESP-01S (ESP8266) auf einem ESP-01S-Relaismodul.
  • Relais an GPIO0, schaltet bei LOW. Das ist eine Annahme für das übliche „ESP-01S Relay“-Modul, am Gerät noch nicht bestätigt. Bei umgekehrtem Verhalten RELAY_ACTIVE_LOW auf false setzen.
  • Das Relaismodul mit 5 V versorgen. Der ESP-01S braucht kurzzeitig bis etwa 300 mA, der 3V3-Pin eines FT232RL-Adapters (≈ 50 mA) reicht nicht.

On-Air-Lampe: Einrichtung

  1. Ohne bekanntes WLAN öffnet die Lampe den Access Point ORS-OnAir-XXXX, Passwort ors-setup, Einrichtungsseite unter http://192.168.4.1.
  2. WLAN (2,4 GHz) wählen, Server-Adresse (Adresse des eigenen Servers) und Port (8393) eintragen, Save.

Die Server-Einstellungen liegen im Flash (LittleFS, Datei /server.cfg).

Sicherheit

  • Das Passwort der Einrichtungs-Access-Points ist für alle Geräte gleich (ors-setup, in der Firmware CONFIG_AP_PASSWORD). Wer es kennt, kann ein Gerät im Einrichtungsmodus umkonfigurieren. Für den Dauerbetrieb ein eigenes Passwort setzen und neu flashen.
  • Die Einrichtungsseite hat keine eigene Anmeldung. Sie ist nur erreichbar, solange das Portal offen ist.
  • /api/sim/status ist bewusst ohne Login erreichbar. Er liefert nur, ob eine Übung läuft, ihren Namen, Startzeit und Raum sowie die Nummer eines laufenden Vor-Starts.

  4. In der Liste zeigt eine Badge, ob das Blatt mit einer Session verknüpft ist. Öffnen zeigt das Blatt, Ansicht/Druck die Druckansicht, Lösen trennt die Verknüpfung, Löschen macht den Link ungültig.

Ausfüllen und verknüpfen (Teilnehmer)

  1. Link öffnen. Felder ausfüllen, gespeichert wird automatisch beim Verlassen eines Feldes. Die Leiste oben bestätigt „✓ gespeichert“.
  2. Startet der Ausbilder eine Simulation, erscheint das Fenster Neue Simulation gestartet. Ja, verknüpfen sendet ab jetzt jede Notiz als Marker, Nein lässt das Blatt privat. Die Frage kommt pro Simulation nur einmal.
  3. Die Marker erscheinen beim Ausbilder unter dem Nutzer Teilnehmer im Format „Blattname: Feld: Wert“. Eine grüne Badge „verknüpft mit …“ zeigt den Zustand, Verknüpfung lösen beendet ihn.
  4. 🗑 Zurücksetzen löscht nach Rückfrage alle Eingaben. Bereits gesetzte Marker bleiben erhalten.
  5. 📲 QR-Code zum Download zeigt einen Code zur Druckansicht des ausgefüllten Blattes. Dort: 🖨 Drucken / PDF oder 💾 Als HTML speichern für eine eigenständige Datei.
Endet die Session, zeigt das Blatt „beendet“ und erzeugt keine Marker mehr. Bei der nächsten Session fragt es erneut.

Logauszug als QR-Code Admin

Für Fälle ohne jede Netzwerkverbindung beim Empfänger (Handy darf nicht ins Server-LAN, keine Mobilfunk-/Internetverbindung garantiert): 📱 QR neben einer Logdatei öffnet einen QR-Code, der die Daten selbst enthält — kein Link, also auch ohne Netzwerk abfotografierbar.

  • Ein QR-Code fasst nur ca. 2 KB. Es passt deshalb nie die komplette Datei hinein, sondern immer nur ein Auszug der neuesten Zeilen bis zu diesem Platzlimit.
  • Häkchen Nur Fehler/Warnungen filtert vorher auf WARN/ERROR-Zeilen — bei knappem Platz passen so mehr relevante Zeilen hinein als bei allen Zeilen inklusive Info-Meldungen.
  • Die Anzeige unter dem Code zeigt, wie viele von wie vielen Zeilen enthalten sind. Für die vollständige Datei bleibt nur Download oder Mail (siehe oben) — das braucht aber eine Netzwerkverbindung.

  3. Gedacht für ein zweites Gerät (z.B. iPad) neben der eigentlichen Simulations-Steuerung — die Seite ist unabhängig von einer laufenden Session nutzbar, auch um Kameras vor dem Start auszurichten.

Je Eingang gibt es Gerät, Label, Gain und Kanäle: leer = alle Kanäle des Interfaces zusammen (Mono), 3 = nur Eingang 3, 1,2 = Stereo aus Eingang 1 links und 2 rechts, 1-8 = Eingänge 1 bis 8 gemischt. Update

Aus der Oberfläche werden nur signierte Pakete installiert. Ein Paket führt bei der Installation Skripte mit Root-Rechten aus; die Signatur stellt sicher, dass es von deinem Build-Rechner stammt und nicht verändert wurde.

  1. Einmalig auf dem Build-Rechner: scripts/sign_update.sh --init erzeugt ein Schlüsselpaar unter ~/.config/openresquesim/. Den privaten Schlüssel sichern und nicht weitergeben.
  2. Einmalig auf jedem Server: den öffentlichen Schlüssel update-signing.pem hinkopieren und sudo install -D -m 644 update-signing.pem /etc/openresquesim/update-keys/build.pem. Das geht nur auf der Konsole, nicht aus der Oberfläche.
  3. Je Update: nach cargo deb das Paket signieren: scripts/sign_update.sh target/debian/openresquesim-server_*.deb. Es entsteht eine .deb.sig-Datei.
  4. Hier .deb und .deb.sig zusammen auswählen und Hochladen. Die Liste zeigt „🔏 signiert“; Installieren ist erst dann möglich.
  5. Das Update läuft im Hintergrund, das Log erscheint darunter. Fehlende Abhängigkeiten holt apt mit (dafür braucht der Server Paketquellen bzw. Internet). Am Ende startet der Dienst neu, die Seite zeigt die neue Version. Eine laufende Session wird dabei beendet.
Fehlt die Signatur oder passt sie nicht, wird nichts installiert, die alte Version läuft weiter. Auf der Konsole geht ein Update jederzeit auch ohne Signatur: sudo apt install ./openresquesim-server_*.deb.

🔐 HTTPS einrichten (für Durchsagen)

Nur die Geräte, von denen aus gesprochen wird, brauchen HTTPS. Viewer, Pager, Notizblätter und Raumlautsprecher laufen weiter über http://…:8393.

Für Ausbilder: Gerät einmalig vorbereiten

  1. Auf dem iPad in Safari http://<server>:8393/ca/ors-rootCA.crt öffnen oder den QR-Code auf der Systemseite (Karte 🔒 HTTPS) scannen. Es erscheint „Profil geladen“.
  2. Einstellungen öffnen, das geladene Profil installieren.
  3. Unter Allgemein → Info → Zertifikatsvertrauen den Schalter für das OpenRescueSim-Zertifikat einschalten.
  4. https://<server>.local:8443/ui öffnen und als Lesezeichen sichern. Der PTT-Knopf hat jetzt Mikrofonzugriff.

Windows: Datei doppelklicken, „Zertifikat installieren“, Lokaler Computer, „Vertrauenswürdige Stammzertifizierungsstellen“. macOS: Datei in den Schlüsselbund ziehen und auf „Immer vertrauen“ setzen.

Für Admins: Server einrichten Admin

  1. Aus der Oberfläche: Optionen → Systemstatus, Karte 🔒 HTTPS. Optional Namen und IPs eintragen (z.B. ors.local, 192.168.1.20) und 🔒 HTTPS einrichten / erneuern drücken. Das Log läuft live mit; am Ende startet der Dienst neu und die Seite verbindet sich von selbst wieder. Die Karte zeigt auch, ob HTTPS aktiv ist und bis wann das Zertifikat gilt.
  2. Alternativ auf dem Server: sudo ./scripts/setup_https.sh, optional mit Namen und IPs, etwa sudo ./scripts/setup_https.sh ors.local 192.168.1.20.
  3. Das Skript erzeugt eine lokale Zertifizierungsstelle, ein Serverzertifikat für 825 Tage, legt das Wurzelzertifikat zum Download ab und setzt ORS_TLS_CERT, ORS_TLS_KEY und ORS_TLS_BIND für den Dienst.
  4. Der Dienst wird neu gestartet und lauscht zusätzlich auf Port 8443. Im Log steht „Listening on https://…“.
  5. Nach 825 Tagen das Skript erneut ausführen. Das Wurzelzertifikat auf den Geräten bleibt gültig.
Rechte: Der Dienst läuft nicht als root; die vom Debian-Paket installierte Regel /etc/sudoers.d/openresquesim erlaubt genau diesen Aufruf, das Skript nimmt nur Hostnamen und IP-Adressen an. Fehlt sie, meldet die Karte „Ohne Rechte“. Ohne Internet müssen mkcert und libnss3-tools installiert sein (Abhängigkeiten des Pakets).
Immer denselben Hostnamen verwenden, der im Zertifikat steht. <hostname>.local löst über Avahi/Bonjour auf, das Skript aktiviert den Dienst mit.

🧰 Fehlerbehebung

Rote Statusleiste „Einloggen“ oder Meldung 401

Die Anmeldung fehlt oder ist abgelaufen. Oben rechts einloggen, die Seite lädt danach neu. Viewer-, QR- und Teilnehmer-Seiten brauchen keinen Login.

Kamera zeigt Schwarzbild mit Beschriftung

Die Kamera liefert kein Bild: URL, Netzwerk und Zugangsdaten prüfen. RTSP-Kameras versucht der Server selbst neu zu verbinden. Beim Raumwechsel ist ein kurzes Schwarzbild normal.

„Pipeline busy“ oder Start dauert lange

Die Pipeline ist gerade im Umbau. Einige Sekunden warten und erneut versuchen. Hilft das nicht, Notfall-Neustart oder als Admin Systemdienst neu starten.

Zuschauer sehen den Stream nicht

QR-Link muss die Netzwerk-IP des Servers enthalten, nicht localhost. Handy und Server müssen im selben Netz sein. Für sehr viele Zuschauer das Bild über den externen Verteiler (RTMP) an einen Streaming-Server geben, der es weiterverteilt.

Marker-Tastenkürzel reagiert nicht

Ist ein Eingabefeld aktiv, wirken nur F13–F24. Zudem muss eine Session laufen. Im Fenster „Marker-Typen verwalten“ prüfen, ob die Taste zugewiesen ist.

Raumlautsprecher ist offline oder hört nichts

Auf dem Pi journalctl -u ors-speaker -f ansehen: stimmt die Server-Adresse in /etc/ors-speaker.conf? Zeigt die Liste „online“, aber nicht „empfängt“, passt die Gruppe nicht zur PTT-Auswahl oder UDP-Port 5004 ist blockiert. Kein Ton trotz „empfängt“: ALSA-Gerät prüfen (aplay -l) und Testton auslösen.

Audio-Interface mit vielen Eingängen liefert nur Kanal 1 und 2

Der Server öffnet Interfaces wie die Scarlett 18i20 jetzt mit allen Kanälen und mischt selbst. Im Audio-Eingang das Feld Kanäle setzen, etwa 5,6 für ein Stereo-Mikrofonpaar an Eingang 5 und 6. Bleibt die Kanalzahl „?“, konnte der Server das Gerät nicht abfragen: arecord -l prüfen und die Karte als plughw:X,0 eintragen. Für die Routing-Matrix der Scarlett Gen 4 braucht der Kernel den Treiber scarlett2 (ab 6.8).

Ältere Sessions fehlen im Debriefing

Nutzer sehen nur Sessions der letzten 24 Stunden. Admins sehen alle.

Aufnahmefehler-Toast während der Session

Der Server meldet Probleme im Aufnahmezweig direkt als Toast. Session stoppen, Speicherplatz und Aufnahmeverzeichnis prüfen, dann neu starten. Admins finden Details in den Service-Logs.

Server startet nicht Admin

Meist fehlen GStreamer-Pakete. Mit gst-inspect-1.0 --version prüfen und sudo ./scripts/install_runtime_deps.sh ausführen. Logs erscheinen auf stdout bzw. in den täglichen Logdateien.

📖 Glossar

Session
Eine aufgezeichnete Simulation mit Name, Start, Dauer, Markern und Aufnahme.
Marker
Zeitmarke innerhalb einer Session mit Typ, Farbe und optionalem Text.
Marker-Typ
Kategorie für Marker, als Standard oder persönlich, mit Farbe und optionaler Taste.
Viewer
Anzeigegerät, das die Viewer-Seite geöffnet hat und Stream, Ruhebild oder Aufzeichnung zeigt.
Raum
Vordefinierte Kombination aus Layout, Kameras je Slot, Audio-Gerät, Raumlautsprechern und Standard-Viewer.
Slot / Layout
Position einer Kamera im zusammengesetzten Bild bzw. die Anordnung aller Slots.
Pipeline
Die Verarbeitungskette aus Kameras, Mischer, Encoder, Aufnahme und Streams.
VOD
Die fertige Aufnahmedatei einer Session für das Debriefing.
WebRTC / RTSP / RTMP
Übertragungswege: WebRTC zum Browser der Zuschauer, RTSP von den Kameras, RTMP zu einem Streaming-Server.
PTT / Voice of Room
Durchsage per gedrückter Taste vom Browser an die Raumlautsprecher (Raspberry Pi) und optional an Viewer.
Vor-Start
Vorbereitete Session, die erst mit „Freigeben“ wirklich startet.
Teilnehmer-Notizblatt
Formular für Teilnehmer, dessen Einträge verknüpft als Marker erscheinen.
